# 🧠 **ЛАБОРАТОРИЯ ИИ КБР — ОПИСАНИЕ ПРОЕКТА**

---

## 1. О ПРОЕКТЕ

**Название проекта:** Лаборатория ИИ КБР (KBR AI Lab)

**Суть:** Это онлайн-платформа, где пользователи могут создавать своих ИИ-агентов, использовать реальных роботов из лаборатории КБР и зарабатывать на продаже своих агентов через маркетплейс.

**Ключевая идея:** ИИ-агент — это цифровой помощник, который получает задачу от пользователя и превращает её в готовый продукт: либо цифровой (модель, расчёт, схема), либо физический (деталь, напечатанная на 3D-принтере).

---

| Разработчики ИИ | Создание агентов и продажа их API |

## 3. ОСНОВНЫЕ СЦЕНАРИИ

### А. Пользователь использует агента
1. Регистрируется
2. Выбирает агента
3. Описывает задачу (текст, файл, голос)
4. Агент выдаёт цифровой результат или ставит задачу роботу
5. Пользователь оплачивает и получает результат

### Б. Пользователь создаёт и обучает агента
1. Нажимает «Создать агента»
2. Выбирает специализацию (Конструктор, Технолог и т.д.)
3. Загружает свои данные для обучения
4. Настраивает внешность агента
5. Публикует в маркетплейсе

### В. Пользователь зарабатывает на агенте
1. Публикует агента в маркетплейсе
2. Устанавливает цену (за вызов или подписку)
3. Платформа берёт комиссию 30%
4. Создатель получает 70%

### Г. Пользователь заказывает физическую деталь
1. Даёт задание агенту
2. Агент создаёт модель и отправляет роботу
3. Робот печатает/сваривает деталь
4. Пользователь получает готовое изделие

## 4. МОДЕЛИ ДАННЫХ (9 МОДЕЛЕЙ)

### 1. **User (Пользователь)**
- Регистрация и авторизация
- Личные данные (ФИО, email, телефон)
- Кастомизация аватара (модель, прическа, цвет кожи, головной убор, аксессуар)
- Финансы (баланс, заработанное)
- Роли: пользователь / создатель / администратор
- Профиль создателя (верификация, локальное приложение)
- Настройки отображения (2D/3D)
- `computerUrl` — ссылка на компьютер пользователя

### 2. **Agent (ИИ-агент)**
- Создание и настройка агента
- Компетенции
- Требования к ресурсам (GPU, CPU, RAM)
- Стоимость (за вызов и подписка)
- Кастомизация внешности (2D и 3D)
- Когнитивные узлы (вход, обработка, выход, память, решение)
- Данные для обучения
- Статистика работы
- `url` — ссылка на самого агента

### 3. **Computer (Вычислитель)**
- Ресурсы (GPU, CPU, RAM, SSD, сеть)
- Свободные ресурсы
- Расположение
- Стоимость использования
- Статус (доступен, занят, обслуживание)
- Визуал (2D и 3D)
- `serverUrl` — ссылка на сервер вычислителя

### 4. **Device (Робот)**
- Типы (3D-принтеры по пластику и металлу, сварщики, фрезеры, ЧПУ)
- Компетенции
- Расположение
- Протоколы обмена (G-code, Modbus, OPC-UA)
- Стоимость (за час и за грамм)
- Узлы и компоненты с координатами, размерами и ориентацией
- Технические характеристики
- Статус и текущее задание
- `ipAddress` — IP адрес робота

### 5. **Task (Задание)**
- Статус выполнения
- Участники (пользователи, агенты, вычислители, роботы)
- Требуемые и выделенные ресурсы
- Связи агентов с роботами
- Связи агентов с вычислителями
- Чат с участниками
- Результат (цифровой или физический)

### 6. **MarketplaceListing (Маркетплейс)**
- Цена за вызов и подписка
- Статистика продаж
- Отзывы и рейтинг
- Статус публикации

### 7. **Transaction (Транзакция)**
- Типы (покупка, подписка, комиссия, вывод, возврат)
- Сумма и валюта
- Связь с агентом или заданием
- Статус и способ оплаты

### 8. **Notification (Уведомление)**
- Типы (обновление задачи, платеж, публикация агента, системное)
- Контент и ссылка
- Статус прочтения

### 9. **ApiKey (API ключ)**
- Хеш ключа (безопасное хранение)
- Префикс для отображения
- Права доступа
- Статус (активен, отозван)
- Статистика использования
- Отдельная коллекция для безопасности

## 6. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

### Бэкенд:
- **Стек:** Node.js, TypeScript, MongoDB, Express, JWT
- **База данных:** MongoDB
- **Контейнеризация:** Docker (MongoDB в контейнере)
- **WebSocket:** Для чата и анимации агентов

### Фронтенд:
- **Стек:** React, TypeScript
- **Рендеринг агентов:** 2D и 3D (Three.js)
- **Анимация:** WebSocket для статусов и движений

### Роботы:
- **Протоколы:** G-код, Modbus, OPC-UA
- **Управление:** Очереди заданий, статусы

## 7. ВНЕШНОСТЬ АГЕНТОВ (2D И 3D)

### 2D режим:
- Спрайт-анимация
- Эмоции (нейтральное, счастье, грусть, злость, задумчивость)
- Лёгкие анимации (дыхание, разговор, работа)

### 3D режим:
- Трёхмерные модели
- Полные анимации (ожидание, разговор, работа, успех, ошибка)
- Кастомизация: цвет тела, цвет кожи, одежда, причёска, аксессуары

### WebSocket-команды для анимации:
```json
{
  "type": "agent_state",
  "agentId": "string",
  "state": "thinking" | "speaking" | "working" | "success" | "error" | "idle",
  "emotion": "happy" | "sad" | "neutral" | "thinking",
  "duration": 3000,
  "message": "текст"
}
```

## 16. СВЯЗИ МЕЖДУ МОДЕЛЯМИ

```
User
  ├── Agent (как creator)
  ├── Computer (как creator)
  ├── Device (как creator)
  ├── Task (как creator и участник)
  ├── MarketplaceListing (как sellerId)
  ├── Transaction (как userId)
  └── Notification (как userId)

Agent
  ├── User (creator)
  ├── Task (через массив)
  ├── MarketplaceListing (через agentId)
  └── ApiKey (через userId)

Task
  ├── User (creator + участники)
  ├── Agent (массив)
  ├── Computer (массив)
  ├── Device (массив)
  ├── agentDeviceConnections → Agent/Device
  └── agentComputerConnections → Agent/Computer
```

## 17. КЛЮЧЕВЫЕ ОСОБЕННОСТИ
